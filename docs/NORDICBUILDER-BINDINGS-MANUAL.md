# Nordic Builder — Правила применения (bindings): мини-мануал

Этот документ объясняет, как через админку управлять **правилами применения макетов** (binding rules) для системных overlay-страниц (например, категории и профили), чтобы не править SQL руками.

## Где находится экран

Админка → **Нордик → Правила применения**

URL обычно такой:

- `/admin/controllers/edit/nordicbuilder/bindings`

## Что такое binding rule

Binding rule — это документ, который говорит системе:

- **если** текущая страница подходит по условиям (matching)
- **то** применять макет с ключом **page_key**

Важно для runtime adapter в текущей версии:

- `page.homepage` трактуется как главная без native body.
- Любое другое правило с префиксом `page.` трактуется как внутренняя страница с native body (`internal_content_generic`).

Ключ документа: `binding_key`.

Рекомендуемый формат:

- `overlay.<kind>.<variant>`

Примеры:

- `overlay.content_category.board`
- `overlay.user_profile.default`

Дополнительно (full takeover страниц):

- `page.homepage`
- `page.marketing`

## Самый простой старт (рекомендуется)

1) Откройте экран **Правила применения**
2) Нажмите **Создать примеры**
3) Откройте правило из списка
4) Поменяйте `page_key` на нужный макет (если нужно)
5) Нажмите **Сохранить правило**

## Быстрый вариант для новичков (из экрана «Страницы»)

Админка → **Нордик → Страницы** → **Новая страница**.

В мастере можно сразу выбрать «Где применять»:

- **Главная страница** → создастся правило `page.homepage` (route_params для homepage)
- **Выборочные страницы (URL-маски)** → создастся правило `page.*` с вашими масками

Если выбрать «Не привязывать сейчас», то будет создан только макет — правило можно добавить позже в разделе **Правила применения**.

## Поля формы (по-простому)

### binding_key (обязательно)
Уникальный ключ правила.

### page_key (обязательно)
Ключ макета, который будет применён. Примеры:

- `ads-category`
- `profile-cover`

### matching.route_params (JSON)
Это самый удобный способ «попасть» в нужный overlay. Пример для категории объявлений типа `board`:

```json
{
  "overlay": "content_category",
  "ctype": "board"
}
```

Поддерживаемые ключи (MVP):

- `overlay`
- `ctype`
- `category_id`
- `category_key`
- `user_id`
- `group_id`

Для full takeover страниц (префикс `page.*`) доступны ключи контекста:

- `ctrl`
- `action`
- `page_type`

Если JSON невалидный — сохранение покажет ошибку.

### matching.url_masks / matching.exclude_masks
Маски URL (по одной на строку). `*` означает «любой хвост».

- `url_masks`: правило применится, если URL совпал хотя бы с одной маской
- `exclude_masks`: правило НЕ применится, если URL совпал хотя бы с одной маской

Если `url_masks` пустой, правило может применяться только по route_params.

### require_https
Если включено — правило применится только на HTTPS.

### fallback.strategy
Стратегия отката, если правило не подошло/не сработало. Для MVP обычно достаточно `theme`.

## Как проверить, что правило работает

- Сохраните правило
- Откройте на сайте соответствующую страницу (категория/профиль)
- Если макет изменился — правило сработало

Если макет не поменялся:

- проверьте `route_params_json` (валидный ли JSON)
- убедитесь, что `page_key` реально существует
- убедитесь, что маски URL совпадают с тем, что в браузере (без домена)

## Частые ошибки

- Пустой `binding_key` или `page_key` → правило не сохранится
- Невалидный JSON в `route_params_json` → будет ошибка в форме
- Опечатка в `page_key` → правило сохранится, но при применении макет может откатиться на дефолт

## Примеры, которые создаются кнопкой

- `overlay.content_category.board` → `ads-category` с `route_params: {overlay: content_category, ctype: board}`
- `overlay.user_profile.default` → `profile-cover` с `route_params: {overlay: user_profile}`

## Примеры для full takeover (как в inthemer)

### Главная страница

Создайте правило:

- `binding_key`: `page.homepage`
- `page_key`: `homepage` (или ваш ключ страницы)
- `route_params_json`:

```json
{
  "ctrl": "",
  "action": "index",
  "page_type": "homepage"
}
```

Это подменит контент главной страницы на выбранный макет (только если правило опубликовано/доступно; черновики видны только админу).

### Выборочные страницы (URL-маски)

Создайте правило:

- `binding_key`: `page.marketing`
- `page_key`: ваш макет
- `url_masks` (по строкам), например:

```
promo/*
landing/*
```
