# Nordicbuilder: Admin UI Smoke Checklist

Этот чек-лист нужен для ручной проверки нового Nordic-styled admin UI после зачистки bootstrap-look в основных экранах builder-а.

Покрываем четыре зоны:

1. `pages`
2. `canvas`
3. `defaults`
4. `shell`

## Подготовка

Перед стартом:

1. Войти под администратором.
2. Убедиться, что установлен `nordicbuilder` и доступна страница `homepage`.
3. Для shell-проверки использовать текущий bridge-screen `landingbuilder/shell`.

Базовые адреса:

1. Страницы: `/admin/controllers/edit/nordicbuilder/pages`
2. Canvas главной: `/admin/controllers/edit/nordicbuilder/canvas/homepage`
3. Глобальные стили: `/admin/controllers/edit/nordicbuilder/defaults`
4. Shell list: `/admin/controllers/edit/landingbuilder/shell`

## Проход 1. Реестр страниц

Что открыть:

1. Открыть `/admin/controllers/edit/nordicbuilder/pages`.

Что должно измениться визуально:

1. Должен открыться экран не в виде старой таблицы, а в виде карточек страниц.
2. Для каждой страницы должны быть видны название, ключ, режим, статус и дата обновления.
3. Должны быть две понятные кнопки: `Предпросмотр` и `Открыть редактор`.
4. Не должно быть ощущения старого bootstrap-list/table как главного UI экрана.

## Проход 2. Открытие canvas

Что открыть:

1. Открыть `/admin/controllers/edit/nordicbuilder/canvas/homepage`.

Что должно измениться визуально:

1. Canvas должен открыться как главный продуктовый экран с темным topbar, живым холстом и двумя выдвижными панелями.
2. Верхние кнопки должны выглядеть как единый Nordic-styled control set, а не как набор стандартных bootstrap buttons.
3. Библиотека слева должна состоять из карточек и pill-like tabs, а не из стандартных list-group элементов.
4. Инспектор справа должен использовать единый visual language для inputs, selects и version cards.

## Проход 3. Device switcher и topbar

Что нажать:

1. Переключить `Компьютер`.
2. Переключить `Планшет`.
3. Переключить `Телефон`.

Что должно измениться визуально:

1. Активное устройство должно явно подсвечиваться в общей capsule-группе.
2. Холст должен менять ширину без визуального развала topbar.
3. Кнопки `Библиотека`, `Инспектор`, `Добавить секцию`, `Глобальные стили`, `Стиль на холсте`, `Предпросмотр`, `Сохранить` должны выглядеть как единый набор, а не как смесь разных bootstrap states.

## Проход 4. Library cards и вставка секции

Что нажать:

1. В библиотеке секций выбрать `Пустая секция`.
2. Затем выбрать любой готовый preset секции.

Что должно измениться визуально:

1. Элементы библиотеки должны выглядеть как product cards с коротким описанием и chip-меткой действия.
2. После вставки секции она должна появиться на холсте и автоматически выделиться.
3. На холсте кнопка удаления секции не должна выглядеть как стандартная bootstrap danger button.

## Проход 5. Inspector controls

Что нажать:

1. Выбрать страницу.
2. Выбрать секцию.
3. Выбрать колонку.
4. Выбрать блок.

Что должно измениться визуально:

1. Для всех этих состояний инпуты и селекты должны выглядеть как единый Nordic control layer.
2. Блок `Эффективный shell` должен отображаться как отдельная summary-card, а не как стандартный bootstrap badge block.
3. Semantic block summary должен открываться в отдельной light-card с нормальной иерархией текста.
4. `История версий` должна выглядеть как список version cards с собственной кнопкой восстановления.

## Проход 6. Widget form bridge

Что нажать:

1. Вставить любой системный виджет.
2. Выделить его.

Что должно измениться визуально:

1. Слева должен увеличиться счетчик виджетов.
2. Справа должна открыться штатная форма виджета.
3. Даже если форма пока использует bridge-разметку, она должна визуально встраиваться в Nordic inspector и не выглядеть как чужой слой.

## Проход 7. Defaults screen

Что открыть:

1. Открыть `/admin/controllers/edit/nordicbuilder/defaults`.

Что должно измениться визуально:

1. Экран должен выглядеть как product-style preview плюс форма справа, а не как старая техническая форма без визуального контекста.
2. Слева должно быть понятно, что это secondary screen, а не главный ежедневный маршрут.
3. Визуальные preview-блоки должны передавать язык Nordic, а не стандартный bootstrap look.

## Проход 8. Shell list

Что открыть:

1. Открыть `/admin/controllers/edit/landingbuilder/shell`.

Что должно измениться визуально:

1. Список shell variants должен быть в виде карточек, а не backend-table.
2. Для каждого variant должны читаться scope, key, header/footer, content layout и active slots.
3. Кнопка открытия variant должна визуально соответствовать новому Nordic admin UI.

## Проход 9. Shell variant

Что нажать:

1. Открыть любой variant из shell list.

Что должно измениться визуально:

1. Экран должен быть разложен на preview shell slots, summary и форму настроек.
2. Активные и выключенные slot cards должны визуально различаться без reliance на bootstrap success/secondary cards.
3. Краткая сводка справа должна читаться как product panel, а не как набор backend box-ов.

## Что фиксировать как баг сразу

Считать проблемой и записывать отдельно:

1. Любой экран, где основной визуальный каркас все еще ощущается как стандартный bootstrap table/list/form UI.
2. Любую смесь старых и новых controls в пределах одного и того же блока интерфейса.
3. Потерю интерактивности после замены visual layer: неработающие device toggles, insert actions, selection states, save или version restore.
4. Поломку package mirror, если установленный пакет после сборки выглядит не так же, как live-шаблоны.

## Минимальный критерий прохождения

Smoke-test считать пройденным, если одновременно выполнено все ниже:

1. `pages`, `canvas`, `defaults` и `shell` открываются без явного возврата к старому bootstrap-look как основному UI.
2. Canvas сохраняет свою рабочую логику: device switcher, insert actions, inspector, versions и preview работают.
3. Shell list и shell variant читаются как продуктовые панели, а не как технические таблицы.
4. Не найдено критических JS/PHP ошибок и визуального рассинхрона между live и package mirror.
