# NordicBuilder P0 план (SEO-first, один HTML) — 2026-04-09

Этот план описывает ближайшие шаги, чтобы конструктор:

- работал с любыми URL и типами контента InstantCMS,
- давал максимальную скорость/SEO через SSR кеш,
- не требовал патчей движка (только точки расширения).

## Что именно хотим получить (простыми словами)

1) На публичном сайте страницы открываются быстро, потому что для них уже есть готовый HTML.
2) Для новости/категории HTML свой (не один на всех).
3) Если в новости поменяли текст — нужные кеши автоматически обновляются.
4) На телефоне/планшете/компе используется один и тот же HTML, а адаптивность делает CSS.

## MVP контексты (самый минимум)

- Запись контента: `content/view` (пример: новость)
- Категория: `content/category`

Решение (зафиксировано): делаем MVP как **(B) запись + категория**.
Главную/статичные страницы добавляем следующим небольшим шагом после стабилизации кеша на контенте.

## P0 задачи (1–2 недели)

### 1) Выбор макета по контексту (Bindings)

- Сделать нормализатор контекста: из текущего запроса получаем “что это за страница”:
  - тип: запись/категория/страница
  - ctype
  - id записи/категории
  - номер страницы пагинации
- По этому контексту выбираем binding (правило применения) и получаем `binding_key`.

Результат: система знает, какой builder-макет применить к `/news/123` и к `/news`.

### 2) Кеш SSR HTML по контексту

- Ввести хранилище кеша “по контексту” (отдельная таблица или расширение существующей).
- Ключ кеша: `binding_key + context_key + theme_signature`.
- На публичном запросе:
  1) пытаемся найти кеш;
  2) если нет — рендерим SSR “на лету”, сохраняем, отдаём.

Результат: первый визит может быть медленнее, но дальше всё очень быстро.

### 3) Автоматическая инвалидация (обновление кеша)

- Подключиться к событиям InstantCMS контента:
  - при изменении записи: сбрасываем кеш `content:view:{ctype}:{id}`
  - при изменении категории: сбрасываем кеш `content:category:{ctype}:{cat_id}:p1` (минимум)
  - при удалении записи: сбрасываем связанные кеши

Результат: после правок в админке люди видят актуальный сайт.

### 4) Ручной rebuild (кнопка для владельца сайта)

- Добавить простую кнопку: “Пересобрать кеш”
  - для выбранного binding
  - или “всё”

Результат: если что-то пошло не так, владелец может быстро восстановить состояние без разработчика.

### 5) Глобальные дизайн-токены и их влияние на кеш

- Ввести `theme_signature` (хеш глобальных токенов).
- При изменении глобальных стилей:
  - либо массово инвалидировать кеш,
  - либо автоматически начать писать новый кеш под новую подпись.

Результат: смена типографики/цветов мгновенно и безопасно отражается на сайте.

## Правила безопасности (важно для коммерческого ZIP)

- Кешировать только для гостей (не для админов/авторизованных пользователей).
- Если кеш недоступен/сломался — не падать: отдавать fallback SSR на лету.
- Все стили builder-а только через `.nb-runtime`.

## Как понять, что всё работает (чеклист проверки)

1) Открыть любую запись (пример: новость).
  - Первый заход может быть чуть медленнее.
  - Второй заход должен быть заметно быстрее (страница уже из кеша).

2) Открыть категорию (список новостей).
  - Повторить: первый заход → второй заход (второй быстрее).

3) В админке InstantCMS изменить текст новости.
  - После сохранения открыть эту же новость на сайте.
  - Должен отображаться новый текст (значит кеш обновился/пересобрался).

4) Изменить заголовок/описание (SEO поля, если они используются в макете).
  - На сайте должны обновиться title/description (если макет их задаёт).

5) Проверка адаптивности.
  - Открыть ту же страницу на телефоне/узком окне.
  - HTML тот же, но внешний вид перестроился стилями (CSS).
