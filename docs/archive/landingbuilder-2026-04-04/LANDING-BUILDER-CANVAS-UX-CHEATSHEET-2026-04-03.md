# Шпаргалка: экран canvas editor в Нордик

## Зачем этот файл

Это короткая рабочая шпаргалка.

Ее задача: быстро видеть перед глазами, как должен выглядеть один главный экран редактора, без перечитывания всех больших техспек.

Подробная архитектура зафиксирована в [LANDING-BUILDER-CANVAS-EDITOR-SPEC-2026-04-03.md](LANDING-BUILDER-CANVAS-EDITOR-SPEC-2026-04-03.md).

## 1. Главный принцип

Пользователь работает не с rows, cols и positions.

Пользователь работает с:

1. секциями;
2. колонками;
3. элементами внутри колонок;
4. переключателями устройств;
5. настройками выбранного элемента.

## 2. Каркас одного экрана

Экран canvas editor должен состоять из четырех зон.

### 2.1. Верхняя панель

Верхняя панель содержит:

1. название страницы;
2. статус `draft/published`;
3. кнопку `Сохранить`;
4. кнопку `Предпросмотр`;
5. device toggles: `Компьютер`, `Планшет`, `Телефон`;
6. переключатель `Структура` / `Контент` при необходимости;
7. breadcrumb назад к списку страниц.

### 2.2. Левая панель

Левая панель это библиотека.

Внутри минимум две вкладки:

1. `Блоки Нордик`
2. `Системные widgets`

Дополнительно позже:

3. `Секции`
4. `Избранное`
5. `Глобальные шаблоны`

Что делает пользователь слева:

1. ищет блок или widget;
2. смотрит preview;
3. перетаскивает его в колонку на холсте.

### 2.3. Центральная область

Центр это сам холст.

На нем должны быть видны:

1. секции страницы сверху вниз;
2. layout секции;
3. колонки внутри секции;
4. все nodes внутри колонок;
5. drop-зоны для drag-and-drop.

Центральная область должна поддерживать:

1. reorder секций;
2. reorder nodes;
3. перенос node между колонками;
4. выделение активного элемента;
5. быстрые действия секции: duplicate, delete, change layout;
6. быстрые действия node: duplicate, hide, delete.

### 2.4. Правая панель

Правая панель это inspector.

Она должна менять содержимое в зависимости от выделения.

Если выбрана секция:

1. layout preset;
2. отступы;
3. фон;
4. visibility;
5. responsive overrides.

Если выбрана колонка:

1. ширина по устройствам;
2. порядок по устройствам;
3. выравнивание;
4. gap;
5. visibility.

Если выбран block node:

1. props блока;
2. dynamic source;
3. mapping;
4. visibility;
5. style options.

Если выбран system widget node:

1. стандартная widget form;
2. widget options;
3. visibility;
4. wrapper behavior;
5. preview settings.

## 3. Канонический сценарий пользователя

Правильный пользовательский путь должен выглядеть так:

1. создать страницу;
2. открыть canvas;
3. добавить секцию;
4. выбрать ей layout;
5. перетащить блоки или widgets в колонки;
6. переключить устройство и проверить поведение;
7. донастроить выбранный элемент справа;
8. сохранить и открыть preview.

## 4. Что обязательно должно быть в первой версии

Для MVP на одном экране нужно обеспечить:

1. несколько секций;
2. layout presets `1col`, `2col_equal`, `2col_sidebar_left`, `2col_sidebar_right`, `3col_equal`;
3. device toggles `Компьютер`, `Планшет`, `Телефон`;
4. builder blocks на холсте;
5. standard widgets на холсте;
6. drag-and-drop между колонками;
7. inspector справа;
8. preview без выхода из логики страницы.

## 5. Что нельзя показывать пользователю

На экране редактора нельзя показывать:

1. `layout_rows`;
2. `layout_cols`;
3. `widgets_bind_pages`;
4. `pos_8`, `pos_9` и другие служебные position names;
5. `col-lg-6`, `order-md-2` и прочие Bootstrap-классы.

## 6. Быстрый продуктовый тест

Экран сделан правильно, если пользователь может ответить себе на 4 вопроса без обучения:

1. Где добавить секцию?
2. Где поменять раскладку на 2 или 3 колонки?
3. Как переключить мобильную версию?
4. Как добавить обычный widget InstantCMS на холст?

Если хотя бы на один вопрос ответ неочевиден, значит UX еще сырой.
