## Второй проход: nested authoring, layers UX и palette expansion

### 1. Убран принудительный автовыбор при root context

- В editor shell введён явный `rootInsertionMode`.
- После очистки selection редактор больше не обязан мгновенно перевыбирать первый scene node.
- Это сделало рабочим сценарий `В корень` как осознанный insertion context, а не как мимолётное состояние до следующего renderAll.

### 2. Layers переведены из плоского списка в иерархическую навигацию

- Layers теперь рендерятся как tree по `parentId`, а не как плоский z-index список.
- Добавлены breadcrumbs вида `Сцена / Parent / Child`.
- Для выбранного insertion context показывается отдельный marker `insert`.
- Для container/group узлов показывается child badge, чтобы вложенность читалась без ручного раскрытия DOM.
- В block card и layers card добавлены явные действия:
  - `В корень`
  - `К parent`

### 3. Nested insertion доведён до локального parent scope

- Новый объект в nested flow по-прежнему создаётся от текущего selection context, но теперь это подтверждено реальным tree-navigation loop.
- Для новых вставок z-index теперь назначается локально внутри текущего `parentId`, а не глобально по всей сцене.
- Это убирает лишний drift при вложенной authoring-сцене, где children и root nodes не должны делить один глобальный insertion порядок.

### 4. Palette расширен после UX-стабилизации

- Для новых типов добавлены секционные inspector-поля в `Контент / Макет / Стиль`, чтобы расширение palette не ломало новую IA.

## Новый planning pass: artboard-first migration

### Что зафиксировано

- После разбора текущего editor UX против Tilda Zero принято решение не начинать следующий кодовый проход вслепую.
- Создан отдельный canonical план artboard-first migration:
  - `docs/nordicblocks/DESIGN-BLOCK-CANVAS-ARTBOARD-FIRST-MIGRATION-PLAN-V1.md`
- В новом плане зафиксировано:
  - artboard-first вместо camera-first UX;
  - локальное изменение высоты по активному breakpoint как default behavior;
  - overflow как свойство artboard, а не побочный эффект viewport;
  - отдельный узкий первый кодовый проход: shell -> height semantics -> overflow parity -> layers/sidebar V2.

### Почему это важно

- Текущая scene/world математика остаётся полезной как implementation layer, но больше не должна определять продуктовый UX.
- Следующий кодовый проход теперь должен строиться вокруг сущности `белый block artboard`, а не вокруг camera offsets и viewport diagnostics.

## Section model pass 1

### Rollback point

- Перед переводом editor к section/free-node semantics создан отдельный checkpoint:
  - snapshot: `snapshot/20260421-141119`
  - DB backup: `backups/db/builders-20260421-141118.sql.gz`

### Что изменено

- В live editor и package mirror сняты root-level bounds для `design_block` элементов.
- Корневые nodes теперь больше не clamp-ятся границами section/grid при:
  - первичной вставке
  - drag перемещении
  - resize
- Ограничения сохранены только для вложенных children внутри `container` и `group`, где bounded host всё ещё ожидаем продуктово.
- Height semantics блока из предыдущего pass сохранена:
  - drag нижнего края меняет только активный breakpoint
  - значение продолжает редактироваться через sidebar field `Высота artboard`
  - массовая синхронизация остаётся только через явный action `Высоту -> все`

### Что проверено

- `get_errors` по live JS и package mirror не показал новых ошибок.
- Кодовая проверка подтвердила, что root-level interaction теперь идёт через `bounds = null`, а не через `getLocalHostSize()` clamp.

### Остаточный риск

- Полный live smoke этого pass из browser tool не завершён, потому что новая вкладка admin editor открылась как неавторизованная и вернула `403`; нужен короткий ручной smoke в живом админ-сеансе.
- Текущая модель уже позволяет free placement для root-level nodes, но section/grid reference frame пока всё ещё выражен через текущую stage-origin semantics, а не через отдельный section object contract.

## Outside object visibility modes pass

### Rollback

- Checkpoint перед pass:
  - snapshot/20260421-144343
  - DB backup: backups/db/builders-20260421-144342.sql.gz

### Что изменено

- В editor runtime добавлен отдельный режим `outsideVisibilityMode` для объектов, выходящих за белый artboard:
  - `auto` показывает объект на сером workspace, когда текущее выделение или активный drag/resize реально вышли за пределы блока.
  - `show` всегда показывает объекты вне блока.
  - `hide` всегда клипует их по artboard в editor view.
- Новый select выведен в карточку `Холст` как `Объекты вне блока`.
- Editor shell теперь переключает overflow не только у stage, но и у canvas workarea, чтобы при `show/auto` объект оставался визуально доступен мышью на сером поле.
- Live template и package mirror снова синхронизированы.

### Что проверено

- `get_errors` по live editor JS/CSS и package mirror не показал новых ошибок.
- В живом admin editor на block `178` после reload появился новый control `Объекты вне блока`.
- DOM smoke подтвердил переключение stage-классов:
  - `nbde-stage--outside-auto`
  - `nbde-stage--outside-show`
  - `nbde-stage--outside-hide`
- Для выделенного объекта при выносе за границу artboard режим `auto` переводит stage в `nbde-stage--outside-visible`.
