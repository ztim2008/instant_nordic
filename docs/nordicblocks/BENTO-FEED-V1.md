# NordicBlocks — Бенто-лента v1

Дата: 2026-04-20

## 1. Что это за блок

Это новый news/editorial block type для NordicBlocks.

Его задача:

1. показывать компактную новостную секцию с живой неровной бенто-сеткой;
2. работать и в ручном режиме, и от данных InstantCMS;
3. оставаться предсказуемым в SSR и в новом inspector-driven editor;
4. давать пользователю простой способ показать больше карточек без ухода в отдельную страницу сразу.

Важно:

1. это не masonry;
2. это не хаотичная сетка;
3. это управляемая бенто-композиция с фиксированными паттернами карточек;
4. блок должен наследовать news/editorial baseline из `swiss_grid`, но не копировать его буквально.

## 2. Как блок называем

Предлагаем фиксировать так:

1. пользовательское название: `Компактная бенто-лента`;
2. технический slug: `bento_feed`.

Почему так:

1. название сразу объясняет идею пользователю;
2. slug короткий и нейтральный;
3. блок остаётся частью news/editorial линии, но не маскируется под очередной preset старого `content_feed`.

## 3. Что в нём должно быть обязательно

### 3.1 Источник данных

Блок должен поддерживать два режима:

1. `manual`;
2. `content_list` от InstantCMS.

Это значит:

1. в демо и ручной сборке можно заполнить карточки руками;
2. в бою блок может брать записи из выбранного content type;
3. mixed manual + dynamic внутри одного списка в v1 не допускается.

### 3.2 Внешний вид

Блок должен быть:

1. компактным;
2. плотным;
3. с неровной, но контролируемой бенто-сеткой;
4. с разным визуальным весом карточек;
5. без развала на мобильной версии.

Ключевое правило:

1. сетка выглядит интересно, но остаётся предсказуемой;
2. не используем свободный masonry-алгоритм;
3. используем 1-2 фиксированных layout-паттерна, которые можно уверенно рендерить и в preview, и в live.

## 4. Какие настройки нужны в v1

### 4.1 Контент секции

1. заголовок секции;
2. описание секции;
3. текст верхней ссылки `Все материалы`;
4. URL верхней ссылки;
5. переключатели показа описания и верхней ссылки.

### 4.2 Данные

1. режим источника: `manual` или `content_list`;
2. выбор content type InstantCMS;
3. лимит карточек на стартовой загрузке;
4. порядок сортировки;
5. при необходимости фильтр по категории или разделу.

### 4.3 Сетка

Это обязательная часть, которую ты отдельно попросил.

Нужны настройки:

1. сколько карточек в ряд на компьютере;
2. сколько карточек в ряд на телефоне;
3. layout preset бенто-сетки;
4. расстояние между header и сеткой;
5. расстояние между карточками, если оно вообще допускается preset-ом.

Практическое ограничение для v1:

1. desktop columns: `2..4`;
2. mobile columns: `1..2`.

### 4.4 Карточка

1. показывать или скрывать изображение;
2. показывать или скрывать рубрику;
3. показывать или скрывать анонс;
4. показывать или скрывать meta;
5. текст CTA карточки;
6. стиль CTA карточки;
7. общий стиль поверхности карточек.

### 4.5 Длинный список

Здесь фиксируем сразу то, что ты хочешь как фишку блока.

В v1 должны быть режимы:

1. `all`;
2. `load_more`;
3. `pagination`.

Но продуктовый приоритет такой:

1. главным режимом считаем `load_more`;
2. кнопка снизу по умолчанию называется `Показать ещё`;
3. `pagination` остаётся вторым допустимым режимом, если пользователю нужна привычная разбивка по страницам.

Нужны настройки:

1. режим длинного списка;
2. текст кнопки `Показать ещё`;
3. сколько карточек показывать сначала;
4. сколько догружать по нажатию;
5. показывать или скрывать нижний блок навигации.

## 5. Что не делаем в v1

1. не делаем masonry;
2. не делаем drag-and-drop ручную раскладку карточек по ячейкам;
3. не делаем смешанный режим manual + dynamic в одной сетке;
4. не делаем backend remote pagination;
5. не делаем бесконечную прокрутку;
6. не делаем отдельный private inspector под этот блок.

## 6. Какой первый практический шаг

Первый правильный шаг такой:

1. зафиксировать этот блок как новый managed block type `bento_feed`;
2. перед кодом сделать checkpoint;
3. поднять scaffold через `scripts/nordicblocks-scaffold-block.php`;
4. профиль брать не hero-like, а `card_collection`;
5. после scaffold сразу прогнать `scripts/nordicblocks-validate-block.php`;
6. только потом доводить render, layout preset и режим `load_more`.

То есть первый реальный кодовый шаг не ручное копирование старого блока, а такой:

1. создать skeleton нового `bento_feed` через scaffold;
2. сделать его на общем новом inspector path;
3. затем уже докручивать бенто-композицию, колонки desktop/mobile и нижний `Показать ещё`.

## 7. Короткий итог

Если совсем коротко, то v1 для этого блока звучит так:

1. новый блок `Компактная бенто-лента` (`bento_feed`);
2. данные из InstantCMS через `content_list` плюс ручной режим;
3. отдельные настройки колонок для desktop и mobile;
4. управляемая бенто-сетка без masonry;
5. основной длинный режим — `Показать ещё` снизу;
6. весь блок должен жить на новом универсальном inspector, без отдельного старого редактора.
