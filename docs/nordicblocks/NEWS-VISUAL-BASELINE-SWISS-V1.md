# NordicBlocks — News Visual Baseline Swiss V1

Дата: 2026-04-19

## 1. Зачем нужен этот документ

`swiss_grid` оказался не просто ещё одним отдельным block type, а первым по-настоящему удачным reusable visual profile для news/editorial направления NordicBlocks.

Этот документ фиксирует не конкретную вёрстку одного блока, а визуальную систему, которую можно переносить в следующие блоки и целые линейки.

Главная задача:

1. сохранить сильную узнаваемую подачу;
2. не скатиться обратно в generic карточки с безопасным gap и декоративным шумом;
3. дать следующим news-блокам общий art direction до начала кода.

## 2. Где это считается каноном

Для задач про news/editorial блоки и будущие сложные линейки этот baseline считается каноническим вместе с:

1. `docs/nordicblocks/NEWS-FAMILY-V1.md`;
2. `docs/nordicblocks/GLOBAL-DESIGN-FOUNDATION-V2.md`.

Разделение ответственности такое:

1. `GLOBAL-DESIGN-FOUNDATION-V2` отвечает за глобальные токены, кнопки, поверхности и shared helpers;
2. этот документ отвечает за композиционный язык news/editorial блоков;
3. конкретный block spec отвечает за то, как именно этот язык применяется в одном block type.

## 3. Арт-разбор: почему Swiss baseline работает

### 3.1 Плотность вместо воздуха

Сильнейшее решение здесь не в декоративных деталях, а в плотности.

Блок воспринимается как единое editorial-поле, а не как набор отдельных карточек, потому что:

1. grid живёт с `gap: 0`;
2. карточки читаются через общие границы, а не через расстояния между ними;
3. ритм создаётся внутренними padding и типографикой, а не пустотами между блоками.

Именно это даёт ощущение взрослой журнальной сетки.

### 3.2 Типографика держит иерархию сильнее, чем декор

Визуальная иерархия строится не на тени, скруглениях и ярких плашках, а на дисциплине текста:

1. заголовок секции крупный и жёсткий;
2. meta-маркер маленький, uppercase и акцентный;
3. заголовок карточки плотный и доминирующий;
4. анонс тише и служебнее;
5. CTA короткий и не спорит с заголовком.

За счёт этого блок остаётся собранным даже при минимуме декоративных средств.

### 3.3 Контраст минималистичный, но не стерильный

Блок не выглядит бедно, потому что контраст строится аккуратно:

1. в основе нейтральная монохромная поверхность;
2. акцент обычно один и работает как редакционный маркер;
3. hover не меняет архитектуру блока, а только слегка оживляет поверхность;
4. изображение остаётся частью контента, а не спецэффектом.

Итог: визуально дорого, но без лишней «премиальности напоказ».

### 3.4 Сетка ощущается как продуктовая фишка

Для NordicBlocks это важно зафиксировать отдельно:

1. плотная grid-подача с `gap: 0` становится узнаваемой фишкой системы;
2. это не случайный stylistic choice, а повторяемый продуктовый приём;
3. следующие news-блоки должны наследовать именно эту дисциплину, даже если композиция будет другой.

## 4. Канонические правила baseline

### 4.1 Сетка

1. По умолчанию news/editorial block должен стартовать с плотной grid-логики.
2. Каноническое значение для grid между карточками: `gap: 0`.
3. Ритм создаётся через border, padding, line-height и размер колонок.
4. Если в новом блоке нужен gap, это должно быть осознанное исключение, а не дефолт.

### 4.2 Поверхности

1. Базовое состояние карточки плоское.
2. Основной разделитель карточек: border, а не box-shadow.
3. Сильная тень в idle-state не является каноном для этой линии.
4. Hover-движение допускается, но только как лёгкое усиление поверхности.

### 4.3 Типографика

1. Иерархия должна читаться за 2-3 секунды даже без изображения.
2. Meta, заголовок карточки, анонс и CTA обязаны быть разведены по роли.
3. Заголовок карточки не должен визуально растворяться в body-тексте.
4. Для inspector-driven размеров не использовать CSS-паттерны, которые мешают прямой реакции editor controls.

### 4.4 Контраст

1. Основа: нейтральные поверхности и строгий текстовый контраст.
2. Акцентный цвет лучше использовать дозированно, обычно через meta, CTA или единичные сигналы.
3. Не превращать блок в витрину из разноцветных карточек.
4. Минималистичный контраст важнее декоративной насыщенности.

### 4.5 Медиа

1. Изображение поддерживает композицию, но не должно держать весь блок в одиночку.
2. Даже без картинки карточка обязана выглядеть законченной.
3. Placeholder и image ratio должны поддерживать строгий ритм сетки.

## 5. Как переиспользовать baseline в следующих блоках

Этот baseline нужно переиспользовать не как копию `swiss_grid`, а как язык.

То есть следующие блоки могут отличаться по композиции:

1. иметь lead-card и rail;
2. иметь asymmetrical editorial split;
3. работать как плотная category wall;
4. работать как archive matrix;
5. работать как mixed hierarchy grid.

Но при этом должны сохранять общие признаки:

1. плотная сетка;
2. ощущение одного editorial-поля;
3. жёсткая типографическая дисциплина;
4. плоские поверхности и контролируемый hover;
5. минималистичный, а не декоративный контраст.

## 6. Что считается правильным наследованием

Правильное наследование baseline выглядит так:

1. новый блок узнаётся как часть одной линии;
2. у него своя композиция, а не просто переставленные те же карточки;
3. он расширяет язык, а не ломает его;
4. он не скатывается в generic SaaS/blog grid.

## 7. Что считается ошибкой

Ошибкой для следующих news-блоков считаем:

1. возврат к безопасным карточкам с заметным gap по умолчанию;
2. избыточные скругления и постоянные тени как главный визуальный приём;
3. потерю плотности ради «воздуха» без редакционной причины;
4. смешение нескольких ярких акцентных цветов внутри одной секции;
5. typography, которая больше не управляет иерархией;
6. визуальные решения, где блок держится только на красивой картинке.

## 8. Практическое правило для новой сложной линейки

Если после `swiss_grid` запускается новая сложная news/editorial линейка, стартовый процесс должен быть таким:

1. сначала проверить, как новый block family опирается на этот baseline;
2. затем зафиксировать, что именно наследуется без изменений;
3. затем отдельно перечислить, где новая линейка сознательно уходит от Swiss baseline;
4. только после этого утверждать block specs и идти в код.

Итоговое правило:

плотная сетка с `gap: 0`, строгая типографика и минималистичный контраст считаются продуктовой фишкой NordicBlocks для news/editorial направления, пока не принято другое отдельное решение.
