# NordicBlocks Worklog — 2026-04-23

## Контекст

- Финальный live pass был сфокусирован не на общем spacing, а на честной parity между admin editor и public runtime для одного и того же `design_block`.
- Первичная жалоба пользователя выглядела как два симптома:
  - между соседними full-section блоками появлялся лишний зазор;
  - на сайте объект визуально уходил вправо относительно того, что видно в editor.
- Критичная ловушка диагностики: сначала сравнивались разные block instance, поэтому до исправления block id comparison часть выводов была ложной.

## Что реально оказалось причиной

После сравнения одного и того же блока `#183` выяснилось:

1. editor live geometry показывал:
  - `artboard 1440x640`
  - `grid 1320`
  - `bleed 60/60`
  - object width `1313`
  - inset left/right `4/3`
2. public runtime рендерил stage width `1000`, из-за чего при той же ширине объекта правый inset становился отрицательным;
3. saved contract в базе при этом содержал legacy branch `width=1200` и `grid.bleedX=160`, но runtime уже должен был жить по editor-stage semantics, а не по голому legacy fallback.

Root cause был двойной:

1. `DesignBlockCssBuilder::resolveStageBranch()` брал width по схеме `contentWidth ?? derived-grid-width` и игнорировал saved `width` как промежуточный fallback;
2. `DesignBlockContractNormalizer::normalizeStageBranch()` при save выбрасывал explicit stage fields editor-а:
  - `contentWidth`
  - `windowWidth`
  - `outerMargin`
  - `bleedLeft`
  - `bleedRight`

Из-за этого даже после ручного сохранения editor продолжал жить с точными artboard/grid numbers в UI, а runtime снова скатывался в legacy-only branch.

## Что исправлено

### 1. Stage gap / container behavior

- В `DesignBlockCssBuilder::baseCss()` закреплён zero-gap root section для `design_block`:
  - section root padding `0`;
  - stage остаётся `margin: 0 auto` для центрирования.

Это убрало лишний межсекционный зазор и не вернуло проблему «липнет к левому краю».

### 2. Runtime stage width semantics

- В `system/controllers/nordicblocks/libs/DesignBlockCssBuilder.php` stage width fallback выровнен с editor:
  - `contentWidth -> width -> derived grid width`.
- То же изменение синхронно внесено в package mirror.

### 3. Save/normalize parity

- В `system/controllers/nordicblocks/libs/DesignBlockContractNormalizer.php` normalizer начал сохранять explicit stage geometry fields, если они пришли из editor contract.
- То же изменение синхронно внесено в package mirror.

После этого блок `#183` был повторно сохранён через live admin editor, и contract/state начал возвращать:

1. `contentWidth = 1320`
2. `windowWidth = 1440`
3. `outerMargin = 60`
4. `bleedLeft = 60`
5. `bleedRight = 60`

## Практическое правило на будущее

Если в design block editor меняются artboard/grid/bleed поля, нельзя считать save path корректным, пока не подтверждено одновременно всё ниже:

1. state endpoint после save возвращает explicit stage geometry;
2. runtime inline style использует эту geometry, а не legacy-derived fallback;
3. сравнение делается на одном и том же block id и одном placement path.

Если любой из этих трёх пунктов не выполнен, parity ещё не доказана.

## Остаточные риски

- Для уже пересохранённого блока `183` parity подтверждена live и считается устойчивой.
