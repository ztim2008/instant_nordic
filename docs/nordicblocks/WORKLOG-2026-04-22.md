## Что сделано

### 1. В `design_block` добавлен новый type `embed`

- Новый элемент добавлен в palette как `Вставка`.
- Type зарегистрирован в server-side allowlist normalizer-а и синхронно перенесён в package mirror.
- Для `embed` введены canonical props:
  - `sourceMode = html|url`
  - `code`
  - `url`
  - `title`
  - `lazy`
  - `allowFullscreen`
  - `sandboxProfile = strict|forms|media|trusted`
  - `referrerPolicy`

### 2. Runtime сделан через sandbox iframe, а не через raw HTML в DOM

- `DesignBlockElementRenderer` рендерит `embed` через отдельную iframe-ветку.
- Для `html`-режима используется `srcdoc` с базовой безопасной оболочкой документа.
- Для `url`-режима допускаются только `http/https` iframe URL.
- В runtime добавлены отдельные sandbox/allow профили, чтобы совместимость и изоляция регулировались явно, а не неявным raw HTML output.

### 3. Editor shell получил полный authoring loop для `embed`

- В `design-block-editor.js` добавлены:
  - palette label/type wiring;
  - default branch с размером `480x320`;
  - inspector-секции `Источник` и `Безопасность и runtime`;
  - canvas preview через iframe;
  - placeholder для пустого embed state.
- В `design-block-editor.css` iframe preview переведён в `pointer-events: none`, чтобы embed не перехватывал selection/resize gestures на холсте.

## Остаточные риски

- Это `v1` embed-flow, а не полный universal embed runtime: некоторые внешние providers могут требовать профиль `trusted` или собственный iframe snippet вместо простого URL.
- Public runtime smoke на размещённом widget path после этого прохода отдельно не выполнялся; обязательный следующий шаг перед релизом — ручная проверка на публичной странице с реальным provider snippet.
- Текущий pass не добавляет provider-specific presets, auto-height messaging и postMessage bridge; если они понадобятся, это уже следующий отдельный scope.
