# NordicBlocks — Старт на 2026-04-22

## Где мы находимся

На конец 2026-04-21 `design_block` уже прошёл несколько взрослых проходов по canvas и inspector, но день завершился не расширением scope, а стабилизацией реального authoring loop внутри editor.

Фактически к утру уже есть:

1. базовый object authoring loop для `text / button / object / photo`;
2. Tilda-like контур правого инспектора `Контент / Макет / Стиль`;
3. layers tree и insertion context для root/nested сценариев;
4. object context menu на canvas и в слоях;
5. hotkeys/group/copy/paste и локальный editor clipboard;
6. photo picker через системный modal с восстановленным write-path для `src`.

Но главное на старте нового дня: редактор уже не в стадии "доказать, что вообще можно", а в стадии "сделать interaction и sidebar предсказуемыми как продукт".

## Главный принцип на завтра

Не расширять фичи раньше, чем будет закрыта стабильность основного UX-контура.

Задача дня не в том, чтобы срочно нарастить ещё режимы, а в том, чтобы довести два связанных участка до честного `v1`:

1. editor interaction на canvas;
2. sidebar/layers/inspector как единый управляющий контур.

Если в течение дня появится соблазн снова расползтись в новые block types, animation, data-binding или большой visual polish, это нужно считать выходом за scope.

## Главный deliverable дня

К вечеру должен быть подтверждён один стабильный сценарий без ручных костылей:

1. пользователь выбирает объект на canvas или в layers;
2. selection, context menu, quick actions и sidebar работают согласованно;
3. в sidebar быстро читаются `Контент / Макет / Стиль` без визуального шума и конфликтующих контролов;
4. layers позволяет безопасно менять порядок, группировать, разгруппировывать и не терять контекст parent/root;
5. photo/object/text/button редактируются без JS runtime ошибок;
6. save/reload возвращает ту же сцену и тот же editing loop.

Если этот сценарий не зелёный, день нельзя считать успешным даже при появлении новых фич.

### Шаг 2. Короткий regression baseline по editor/sidebar

Первое практическое действие дня:

1. открыть рабочий block `178`;
2. проверить selection на `text / button / object / photo`;
3. проверить right click на canvas, на layers и на текстовом содержимом;
4. проверить `Ниже / Выше / Вперёд / Назад / В корень / К parent`, если кнопки доступны в текущем UI;
5. проверить `Ctrl/Cmd+C`, `Ctrl/Cmd+V`, `Ctrl/Cmd+G`, `Shift+Ctrl/Cmd+G`;
6. проверить photo picker: `Выбрать -> применить -> Очистить`;
7. проверить save/reload на том же block.

Если здесь находится регрессия, день уходит не в развитие sidebar, а в локальную стабилизацию до зелёного baseline.

### Шаг 3. Сузить редакторские проблемы до одного короткого списка

До правок нужно руками зафиксировать только реальные remaining gaps.

Список должен быть коротким и продуктовым, например:

1. что в sidebar мешает читать выбранный объект быстрее всего;
2. где layers ещё ломает контекст или теряет предсказуемость;
3. где quick actions дублируют друг друга или конфликтуют;
4. где canvas interaction ещё даёт нестабильность при клике, reorder или nested selection.

Не писать общий список пожеланий. Нужен только перечень реальных UX-дефектов следующего прохода.

### Шаг 4. Sidebar pass как единый IA-проход

Основной продуктовый фокус дня: привести правую панель к более взрослому состоянию без раздувания количества режимов.

Что считаем приоритетом:

1. ясная верхняя зона выбранного элемента;
2. быстрые действия без дублирования и без визуального мусора;
3. читаемый порядок секций `Контент / Макет / Стиль`;
4. одинаковый паттерн для `text / button / object / photo`;
5. минимум случайных полей, которые не помогают текущему authoring loop.

Что не делать в этом шаге:

1. не строить новый mega-inspector;
2. не уходить в отдельные частные shell-панели под каждый тип;
3. не добавлять новые feature-блоки только ради визуальной полноты.

### Шаг 5. Layers/context-menu pass как единый interaction-проход

После sidebar-IA пройти только те interaction gaps, которые реально мешают authoring loop.

Минимальный фокус:

1. reorder должен быть предсказуемым и визуально объяснимым;
2. group/ungroup не должен терять selection context;
3. right click не должен конфликтовать с pointer/select path;
4. text selection/edit mode не должен ломать object-level context menu;
5. root/parent context должен читаться одинаково в layers и в block card.

### Шаг 6. Финальный smoke и cleanup

Перед концом дня обязательно:

1. live smoke на одном рабочем block;
2. если нужен разрушительный сценарий, то только на отдельном временном block;
3. save/reload после последнего UX-pass;
4. cleanup временных блоков, widget binds и тестового контента;
5. запись факта в worklog в тот же день.

## Что нельзя делать завтра

1. Не начинать новый большой runtime refactor без отдельного checkpoint.
2. Не расширять palette новыми типами.
3. Не уводить день в animation/effects pass.
4. Не смешивать sidebar IA-pass с новой архитектурой block system.
5. Не оставлять временные smoke-артефакты в рабочем блоке.

## Что считать успешным днём

День считается успешным, если одновременно выполнены условия:

1. editor/sidebar regression baseline зелёный;
2. найден и закрыт короткий список реальных UX gaps, а не размыт косметический backlog;
3. sidebar читается лучше и не расширен лишними режимами;
4. layers/context menu не дают новых runtime ошибок;
5. save/reload подтверждён после финального прохода;
6. день завершён записью в worklog с рисками и rollback point.
