# NordicBlocks Internal Block Catalog — UI Section Decision

Дата: 2026-04-23

## 1. Статус документа

Этот документ фиксирует решение по названию будущего раздела каталога внутри NordicBlocks.

Важно:

1. это не UI implementation spec;
2. это decision-doc для продукта и навигации;
3. цель документа — заранее снять расплывчатость в naming и entry-point semantics.

## 2. Проблема

Для будущего internal catalog внутри компонента нужно одно ясное название раздела.

Если название будет слишком техническим,
пользователь не поймёт, что внутри готовые installable sections.

Если название будет слишком магазинным,
оно утащит продукт в ложное ощущение marketplace или paid store,
чего в MVP быть не должно.

## 3. Рассмотренные варианты

### 3.1 Каталог

Плюсы:

1. коротко;
2. понятно по-русски;
3. не обещает магазин;
4. подходит для free curated library.

Минусы:

1. само по себе слово слишком общее;
2. без контекста не ясно, что это именно каталог блоков.

### 3.2 Каталог блоков

Плюсы:

1. максимально прямо объясняет содержимое;
2. хорошо работает в навигации и заголовке экрана;
3. не выглядит как тарифная или коммерческая зона;
4. хорошо масштабируется для future families.

Минусы:

1. чуть длиннее, чем просто `Каталог`;
2. менее брендово, но это допустимо для MVP.

### 3.3 Библиотека блоков

Плюсы:

1. звучит мягко и content-friendly;
2. хорошо передаёт идею набора готовых решений.

Минусы:

1. слабее подчёркивает browse/install semantics;
2. может путаться с уже установленными локальными блоками.

### 3.4 Магазин блоков

Отклоняется.

Причины:

1. слишком рано вносит store semantics;
2. противоречит free internal MVP;
3. визуально и продуктово обещает то, чего пока нет.

## 4. Решение

Для MVP фиксируется название раздела:

`Каталог блоков`

Это каноническое продуктовое имя будущего entry-point внутри NordicBlocks.

## 5. Как использовать это имя

### 5.1 В навигации

Основное имя раздела:

`Каталог блоков`

### 5.2 В заголовке экрана

Основной заголовок экрана тоже должен быть:

`Каталог блоков`

### 5.3 Во внутренних текстах

Допустимо короткое упоминание `каталог`,
если контекст уже очевиден.

## 6. Почему не просто `Каталог`

На уровне навигации слово `Каталог` слишком нейтральное.

`Каталог блоков` лучше потому что:

1. мгновенно объясняет сущность;
2. не требует дополнительного пояснения в меню;
3. помогает отличить новый раздел от списка уже существующих блоков.

## 7. Почему не `Библиотека блоков`

`Библиотека блоков` остаётся допустимым языком для описания концепции,
но не рекомендуется как основное имя entry-point.

Причина:

для MVP важнее подчеркнуть browse/install loop,
а не просто факт хранения набора элементов.

## 8. Decision summary

Фиксируется следующее:

1. каноническое имя раздела — `Каталог блоков`;
2. слово `магазин` не использовать в MVP naming;
3. `библиотека` допустима как вторичный descriptive language, но не как primary section label.
