## Process decision: scaffold as default path

- По итогам stage 3 и первого production-ориентированного hero через generator зафиксировано рабочее правило: для новых NordicBlocks managed block types в рамках поддерживаемых scaffold profiles стандартный путь теперь scaffold + validator, а не ручное копирование block directory.
- Это правило продублировано в process docs и стартовых агентских инструкциях, чтобы следующая сессия не возвращалась к manual-first подходу без явной причины.

## Process clarification: scaffold baseline != preview parity

- По ходу live-доводки hero-панелей дополнительно зафиксирована важная граница stage 3: scaffold + validator закрывают structural bootstrap и managed runtime registration, но не гарантируют instant draft-preview parity в editor.
- Текущий `editor_hero_v2` работает как server-backed iframe shell: draft меняется в браузере, затем autosave отправляет contract на сервер, и только после успешного save shell делает reload iframe. Поэтому визуальное обновление после autosave само по себе не доказывает проблему generator-а; сначала нужно проверять preview transport layer.
- `BlockContractNormalizer` для managed blocks зафиксирован как compatibility bridge между legacy props storage и contract-first runtime. Его нужно держать минимальным и использовать как persistence adapter, а не как место для новой block-specific preview логики.
- Для следующих сессий добавлено операционное правило: если баг проявляется как `preview не меняется мгновенно`, расследование начинается с editor shell; если баг проявляется как `save/reload ломает значения`, расследование начинается с managed normalizer round-trip.

## Visual CSS MVP-B implementation

- Для persistence слоя добавлены отдельные backend actions `block_css_state` и `block_css_save`, а `block_edit` теперь прокидывает editor shell их URLs только если schema уже поднята в БД.
- В `modelNordicblocks` добавлен current-state storage для block CSS overlay через таблицу `cms_nordicblocks_block_css`, versioning на уровне current document и cache invalidation после save/delete.
- Важно: persisted слой хранит не final document-wide CSS, а canonical target-document по разрешённым keys (`title`, `body`, `accentSurface`, `bodySurface`). Это сознательное отличие от наивного raw-css хранения: runtime CSS компилируется server-side под конкретный instance scope, чтобы один saved overlay не утекал на все `hero_panels_wide` на странице.
- `block_canvas`, public `view` action и widget `nordicblocks_page` теперь выпускают persisted overlay server-side: CSS компилируется под instance selector `#block-<uid>` и инлайнится рядом с конкретным block output.
- Editor overlay module получил persistent mode: load saved document, version-aware save, revert-to-saved и сохранение separate from block contract.

## Universal Visual Inspector decision

- По итогам отдельного product-решения visual editing больше не рассматривается как hero-only или block-by-block CSS initiative.
- Зафиксирован жёсткий принцип: NordicBlocks идёт в `universal visual inspector` как primary editor path, где canvas click выбирает canonical entity, а inspector открывает русские contract-first controls через общий registry/capability runtime.
- Текущий visual CSS overlay слой сохраняется, но переводится в secondary роль: selector-safe fallback для локального fine tune там, где contract-first control ещё не покрывает сценарий.
- Для формальной приёмки направления создан отдельный документ `docs/nordicblocks/UNIVERSAL-VISUAL-INSPECTOR-GO-NO-GO-BLUEPRINT.md`; если первая фаза не даёт единый сильный visual UX минимум на нескольких block types, инициативу нужно закрывать, а не «дотягивать потом».
- Для реализации без возврата в one-off решения создан отдельный day-by-day план `docs/nordicblocks/UNIVERSAL-VISUAL-INSPECTOR-IMPLEMENTATION-PLAN.md`.
