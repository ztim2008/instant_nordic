## Generator / validator technical spec

- Зафиксировано отдельное ТЗ на внутренний scaffold + validator pipeline для новых NordicBlocks block type.
- Документ: `docs/nordicblocks/BLOCK-SCAFFOLD-VALIDATOR-SPEC-V1.md`.
- В ТЗ закреплены обязательные scaffold files, central integration patch-points, package mirror sync, docs trail и блокирующий DS guard: scaffold не должен проходить, если новый блок нарушает Global Design Foundation.

## Scaffold / validator stage 1

- Добавлен первый исполняемый этап scaffold pipeline:
  - `scripts/nordicblocks-scaffold-block.php`
  - `scripts/nordicblocks-validate-block.php`
  - `scripts/nordicblocks-scaffold-lib.php`
- На этом этапе генератор работает как dry-run preflight: собирает blueprint, проверяет registry/profile/dependency rules, строит план обязательных create/patch files и роняет запуск при нарушении DS guard.
- Validator уже умеет в двух режимах: проверка planned blueprint и structural validation существующего block type по manifest/schema/render, first-wave registration, contract support, package mirror parity и checklist entry.

## Scaffold / validator stage 2

- В scaffold добавлен `--apply` режим с обязательным `--checkpoint=<git-tag>`: теперь generator реально пишет `manifest.php`, `schema.json` и `render.php` в live и package mirror.
- Generated block files теперь маркируются как managed scaffold через `generator` metadata, чтобы validator мог отличать новые scaffold blocks от legacy block types.
- Existing-block validator получил compatibility layer: для legacy блоков architectural debt теперь помечается как warning/legacy debt, а для managed scaffold blocks те же нарушения остаются блокирующими error.

## Scaffold / validator stage 3

- Добавлен dynamic runtime integration слой для managed scaffold block types через `ManagedScaffoldRegistry`, чтобы новые slug не требовали ручного расширения central first-wave/runtime registries.
- Обновлены `model.php`, `BlockContractNormalizer.php`, `BindingMapper.php` и `DataSourceResolver.php` в live и package mirror: managed scaffold block теперь автоматически проходит first-wave detection, contract normalization, source resolution и binding mapping по profile/source-mode из scaffold metadata.
- `scripts/nordicblocks-scaffold-lib.php` теперь в apply-режиме не только пишет block files, но и синхронизирует `docs/checklists/NEW_BLOCK_CHECKLIST_STATUS.json` и auto-generated scaffold registry section внутри family doc.
- CLI help scripts переведены на stage 3 semantics; следующий шаг после scaffold apply по-прежнему обязательный: ручной live smoke и подтверждение реального UX/runtime поведения.
- Отдельный usage/doc файл по процессу: `docs/nordicblocks/BLOCK-SCAFFOLD-PIPELINE-STAGE3.md`.
