# NordicBlocks — Старт на 2026-04-20

## Где мы находимся

На конец 2026-04-19 первая фаза `Universal Visual Inspector` формально принята с verdict `GO`.

Это значит:

1. общий inspector path доказан на pilot blocks;
2. новые truthful gaps в `catalog_browser` закрыты через shared system, а не через частные шаблоны;
3. editor smoke и отдельный public/widget smoke уже подтверждены;
4. дальше мы идём не в режим "ещё один эксперимент", а в режим аккуратного расширения и стабилизации.

## Главный принцип на завтра

Не расползаться.

Задача дня не в том, чтобы срочно добавить много нового, а в том, чтобы:

1. закрепить уже принятый universal path;
2. подготовить безопасную вторую волну rollout;
3. не потерять ясность, что является каноном, а что нет.

## Порядок работы на завтра

### Шаг 1. Короткий вход в контекст

Сначала открыть только эти документы:

1. `docs/nordicblocks/START-2026-04-20.md` — этот файл как главный маршрут дня;
2. `docs/nordicblocks/UNIVERSAL-VISUAL-INSPECTOR-IMPLEMENTATION-PLAN.md` — как канонический roadmap;
3. `docs/nordicblocks/WORKLOG-2026-04-19.md` — как фактический итог вчерашнего дня.

Новый агент не должен начинать с archaeology по всему репозиторию.

### Шаг 2. Зафиксировать regression baseline

Первое практическое действие дня:

1. прогнать короткий regression smoke по pilot blocks `#121–#125`;
2. подтвердить, что editor selection, design panels и reload-safe flow не регрессировали;
3. отдельно быстро проверить `catalog_browser` на public runtime только как sanity-check, без нового временного прод-размещения если это не требуется.

Если здесь находится регрессия, день уходит не в rollout, а в стабилизацию.

### Шаг 3. Выбрать следующий block type для второй волны

После regression smoke выбрать только один следующий block type.

Критерии выбора:

1. block должен расширять shared system, а не требовать отдельный editor shell;
2. block должен добавлять полезный новый сценарий, а не дублировать уже закрытый pilot;
3. block должен быть реалистичным для contract-first rollout в рамках одного рабочего дня.

Если кандидат требует новый private inspector path, его не брать.

### Шаг 4. Сделать только discovery и rollout-map для этого блока

До больших правок сначала собрать для выбранного блока короткую карту:

1. какие canonical entities уже есть;
2. какие entity markers отсутствуют в SSR markup;
3. каких capabilities/panels не хватает;
4. что уже может shared registry;
5. где реально нужен normalizer/render/CSS pass.

Цель этого шага: понять объём truthful gaps до кодовых изменений.

### Шаг 5. Только потом идти в implementation

Если rollout-map понятен и не требует разлома архитектуры:

1. довести block через тот же shared contour;
2. сохранить live/package parity для кода;
3. завершить день editor smoke и короткой записью в worklog.

## Что нельзя делать завтра

1. Не создавать новый block-specific inspector shell.
2. Не уходить в overlay-first editing как в основной UX.
3. Не брать два новых блока одновременно.
4. Не смешивать stabilisation day и большой refactor unrelated parts.
5. Не оставлять временные widget binds или smoke артефакты без cleanup.

## Что считать успешным днём

День считается успешным, если выполнено одно из двух:

1. либо regression baseline закреплён и выбран следующий block type с чистой rollout-map;
2. либо выбранный block type реально доведён через shared path без появления private inspector logic.

День не считается успешным, если мы просто накопили ещё один слой локальных исключений.
