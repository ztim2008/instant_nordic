# Nordic Builder: куда мы идем и зачем

Мы строим Nordic Builder как визуальный конструктор страниц для InstantCMS, в котором можно работать быстро и понятно: собирать страницу на холсте, видеть результат сразу и не погружаться в технические детали.

Сегодня на рынке часто встречаются две крайности: либо «красивый редактор без системности», либо «мощный, но сложный инженерный интерфейс». Наша цель - взять лучшее из обоих подходов: дать удобный визуальный опыт для редактора и при этом сохранить надежную архитектуру под капотом.

## Какой вектор развития

Мы идем в сторону visual-first продукта:

- главный экран - рабочий canvas;
- пользователь собирает секции и блоки вокруг реального контента страницы;
- интерфейс становится русскоязычным и дружелюбным для новичков;
- технические сущности (контракты, JSON, storage) остаются внутренним слоем для команды.

Отдельный акцент - единый runtime без расхождений preview/live: то, что пользователь видит в редакторе, должно предсказуемо совпадать с тем, что увидит посетитель сайта.

## Что это дает владельцу сайта

1. Быстрее запуск и редактирование страниц без разработчика.
2. Понятный сценарий работы: секции, блоки, стили, контент.
3. Стабильный серверный рендеринг HTML на PHP и аккуратная интеграция с темой.
4. Меньше риска «магии» и скрытых конфликтов между редактором и live-версией.

## Что это дает команде

1. Четкая архитектурная граница между UI и данными.
2. Масштабируемая модель блоков и секций.
3. Возможность подключать данные InstantCMS через единый adapter-layer, не ломая визуальные блоки.
4. Проще развивать продукт по этапам: foundation -> vertical slice -> editor core.

## Что дальше

Следующий шаг - закрепить Data Adapter Layer: единый API источников данных для блоков (ручные данные, меню, контент, текущий пользователь/запись) с унифицированным форматом ответа. Это позволит делать собственные UI-блоки в конструкторе и опционально подключать к ним данные InstantCMS без усложнения интерфейса для пользователя.

Важно по терминологии: в Nordic Builder мы говорим о классическом серверном рендеринге PHP (InstantCMS), а не о JS-SSR в смысле Next.js/Nuxt (изоморфный JavaScript на сервере и клиенте).

Nordic Builder развивается как продукт, в котором редактору удобно работать каждый день, а команде удобно безопасно и предсказуемо развивать систему.
