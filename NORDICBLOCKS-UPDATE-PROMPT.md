# NordicBlocks Release Prompt

Документ с готовыми формулировками, которыми можно просить агента выпустить релиз NordicBlocks без лишних уточнений.

## 1. Стандартный релиз

```text
Выпусти релиз NordicBlocks версии X.Y.Z.
Сделай полный release cycle по стандартному workflow репозитория:
1. создай checkpoint;
2. синхронизируй версию;
3. обнови changelog и кратко запиши, что вошло в релиз;
4. прогоняй preflight и нужный smoke по изменённому scope;
5. собери install и update архивы;
6. проверь итоговые артефакты;
7. в конце дай мне короткий отчёт:
	- какой файл отдавать для первой установки;
	- какой файл отдавать для обновления;
	- что вошло в релиз;
	- что проверено;
	- какие риски остались;
	- какая rollback-точка актуальна.
```

## 2. Короткая команда

```text
Выпусти релиз NordicBlocks версии X.Y.Z по стандартному workflow репозитория: checkpoint, version sync, changelog, preflight, install/update архивы и финальный отчёт с rollback-точкой.
```

## 3. Hotfix-релиз

```text
Выпусти hotfix-релиз NordicBlocks версии X.Y.Z.
Нужен минимальный безопасный change-set без лишних побочных правок.
Сделай checkpoint, обнови версию, заполни changelog, прогони узкий smoke по затронутому месту, собери install/update архивы и в конце отдельно напиши, какой баг исправлен и какие риски остались.
```

## 4. Релиз с обязательным live smoke

```text
Выпусти релиз NordicBlocks версии X.Y.Z.
Перед сборкой архивов обязательно сделай live smoke в редакторе и на публичной странице, если change-set затрагивает runtime/editor parity.
После этого собери install/update архивы и в финале сообщи, что именно проверено в live.
```

## 5. Что лучше всегда указывать агенту

- целевую версию `X.Y.Z`;
- нужен ли обязательный live smoke;
- это обычный релиз или hotfix;
- нужен ли install-архив, update-архив или оба;
- нужен ли короткий итог для клиента или команды.

## 6. Ожидаемый финальный ответ агента

Проси, чтобы в конце агент всегда дал один и тот же минимум:

1. install-файл для первой установки;
2. update-файл для обновления;
3. что вошло в релиз;
4. что проверено;
5. остаточные риски;
6. rollback-точку.

## 7. Быстрый практический пример

```text
Выпусти релиз NordicBlocks версии 0.1.2.
Сделай это по стандартному workflow репозитория: checkpoint, version sync, changelog, preflight, install/update архивы и финальный отчёт.
Если change-set затрагивает editor/runtime, обязательно сделай live smoke в редакторе и на публичной странице.
```

## 8. Если нужен только update-пакет

```text
Собери update-релиз NordicBlocks версии X.Y.Z без отдельного fresh install сценария.
Сделай checkpoint, version sync, changelog, preflight, update-архив и финальный отчёт с тем, что изменено, что проверено и какая rollback-точка актуальна.
```
